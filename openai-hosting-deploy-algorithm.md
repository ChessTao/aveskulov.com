# Алгоритм публикации сайта через OpenAI Hosting

Этот алгоритм начинается с пункта 3 исходного плана: создание новой production-версии в OpenAI Hosting.

## 3. Создать новую production-версию в OpenAI Hosting

<span style="color: #15803d;">🟢 Выполнено: создана версия 7 в OpenAI Hosting из коммита `3722162c664b7538c4f1abee316a58787cf60e0d`.</span>

Перед созданием версии убедиться, что:

- проект собран командой `npm.cmd run build`;
- рабочее дерево git чистое;
- все изменения закоммичены;
- нужные переменные окружения уже заданы в OpenAI Hosting:
  - `CAMP_SIGNUP_WEBHOOK_URL`;
  - `CAMP_SIGNUP_WEBHOOK_SECRET`.

Текущий проект уже связан с OpenAI Hosting через файл `.openai/hosting.json`.

В этом проекте используется:

```text
project_id: appgprj_6a5f7251b6ac8191a9ba89e00bd9b6bc
```

Как это делается:

1. Попросить Codex создать новую версию сайта в OpenAI Hosting.
2. Codex должен использовать уже существующий `project_id` из `.openai/hosting.json`.
3. Codex должен сохранить версию из текущего закоммиченного состояния проекта.
4. Для версии должен использоваться последний commit SHA, то есть тот коммит, который содержит актуальный код.
5. После сохранения версии Codex получит идентификатор версии.

Важно: версию нужно создавать только после коммита. OpenAI Hosting должен получить именно то состояние проекта, которое зафиксировано в git.

## 4. Задеплоить сохранённую версию

<span style="color: #15803d;">🟢 Выполнено: версия 7 задеплоена в production.</span>

После создания версии нужно развернуть её в production.

Как это делается:

1. Попросить Codex задеплоить только что сохранённую версию.
2. Codex должен деплоить именно сохранённую версию, а не произвольное локальное состояние.
3. После деплоя OpenAI Hosting выдаст production URL.
4. Если статус деплоя не финальный, нужно попросить Codex проверить статус деплоя.
5. Когда статус станет успешным, открыть production URL и проверить сайт.

Важно: каждый деплой OpenAI Hosting является production-деплоем. Не деплоить случайные или незакоммиченные изменения.

## 5. Добавить custom domain `www.aveskulov.com`

После успешного production-деплоя нужно привязать домен.

Как это делается:

1. Попросить Codex добавить custom domain:

```text
www.aveskulov.com
```

2. Codex должен использовать тот же `project_id` из `.openai/hosting.json`.
3. OpenAI Hosting вернёт DNS-записи для домена.
4. Обычно для `www` это будет `CNAME`.
5. Нужно скопировать DNS-запись из ответа OpenAI Hosting.

## 6. Добавить DNS-записи у регистратора домена

В панели управления доменом `aveskulov.com` нужно открыть DNS-настройки.

Добавить запись для:

```text
www
```

Тип записи обычно:

```text
CNAME
```

Значение взять из ответа OpenAI Hosting.

После сохранения DNS-записи подождать обновления DNS. Обычно это занимает от нескольких минут до нескольких часов.

## 7. Проверить статус custom domain

После добавления DNS-записи нужно проверить, увидел ли OpenAI Hosting новую DNS-настройку.

Как это делается:

1. Попросить Codex проверить или обновить статус custom domain.
2. Если домен ещё не подтверждён, подождать и повторить проверку.
3. Когда домен подтверждён, OpenAI Hosting должен также выпустить SSL-сертификат.
4. После этого сайт должен открываться по адресу:

```text
https://www.aveskulov.com
```

## 8. Настроить корневой домен `aveskulov.com`

Для основного домена без `www` есть два варианта.

Рекомендуемый вариант:

- использовать `www.aveskulov.com` как основной адрес;
- настроить редирект с `aveskulov.com` на `www.aveskulov.com`.

Если OpenAI Hosting поддерживает apex-домен для этого проекта, можно отдельно добавить:

```text
aveskulov.com
```

Тогда OpenAI Hosting выдаст DNS-записи типа `A` или другие записи для корневого домена.

<span style="color: #15803d;">🟢 Выполнено для текущего production URL `https://aveskulov-chess-coaching.vdaveskulov.chatgpt.site`: главная страница, `best-games`, Stockfish JS/WASM, базовая API-валидация и запуск движка проверены.</span>

## 10. Проверить форму Camps

На вкладке `Camps`:

1. Ввести тестовый email.
2. Поставить галочку согласия.
3. Нажать `Notify me`.
4. Проверить, что на странице появилось сообщение об успехе.
5. Открыть Google Sheet.
6. Проверить, что новая строка появилась в листе `Endgame Camp`.

Если строка не появилась:

- проверить переменные окружения в OpenAI Hosting;
- проверить, что Apps Script развернут как новая версия;
- проверить, что `WEBHOOK_SECRET` в Apps Script совпадает с `CAMP_SIGNUP_WEBHOOK_SECRET` в OpenAI Hosting.

## 11. Проверить форму Contact

На вкладке `Contact`:

1. Заполнить `Name`.
2. Заполнить `Email`.
3. При желании заполнить `Chess level`.
4. Заполнить `Message`.
5. Нажать `Send message`.
6. Проверить, что на странице появилось сообщение об успехе.
7. Открыть Google Sheet.
8. Проверить, что новая строка появилась в листе `Contact form`.
9. Проверить, пришло ли email-уведомление.

Если строка появилась, но письмо не пришло, возможно Apps Script нужно повторно авторизовать для `MailApp.sendEmail`.

## 12. Проверить защиту от прямого спама

В Apps Script есть секрет:

```js
WEBHOOK_SECRET
```

Сайт отправляет тот же секрет из серверной переменной:

```text
CAMP_SIGNUP_WEBHOOK_SECRET
```

Если кто-то отправит запрос напрямую в Apps Script без секрета, Apps Script должен ответить:

```text
Unauthorized
```

Это не полноценная антиспам-система, но хороший базовый слой защиты.

## 13. Финальная проверка

После успешного теста:

- сохранить production URL;
- сохранить DNS-записи;
- сохранить Apps Script URL;
- убедиться, что секрет не лежит в публичном коде;
- проверить, что `.env` и `.env.local` добавлены в `.gitignore`;
- проверить, что Google Sheet получает заявки.

После этого сайт можно считать опубликованным.
